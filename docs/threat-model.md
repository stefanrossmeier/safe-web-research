# Threat Model

## Status

Initial threat model. This document evolves with the implementation.

## Security Objective

Safe Web Research treats all Internet-derived content as untrusted.

Security must not depend on the LLM correctly identifying or resisting prompt injection.

A compromised or manipulated model must not gain authority beyond the hard capabilities exposed by the trusted application layer.

## Assets

- Search provider credentials
- LLM provider credentials
- Caller-provided data
- Host and internal network
- Local filesystem
- Research integrity
- Source provenance
- Cost and resource budgets

## Untrusted Inputs

- Search queries generated by models
- Search results
- Search snippets
- URLs
- DNS responses
- Redirect targets
- HTTP headers
- HTML
- Plain text
- Future document formats
- LLM outputs

## V1 Non-Goals

V1 does not provide:

- Browser automation
- JavaScript execution
- Website authentication
- Arbitrary page interaction
- Persistent memory
- File downloads
- Shell access
- Filesystem mutation
- Email or messaging actions
- Arbitrary external tools

## Primary Threat Classes

### Prompt Injection

Web content may contain instructions intended to alter model behavior.

### SSRF

Attacker-controlled URLs may attempt access to private or privileged network resources.

### Data Exfiltration

Sensitive information may be encoded into search queries, URLs, requests, or model-provider traffic.

### Excessive Agency

The research system must not gain capabilities unrelated to research.

### Resource Exhaustion

Research loops, downloads, redirects, searches, and model calls must be bounded.

### Misinformation and Source Manipulation

Search results and retrieved pages may be false, stale, duplicated, adversarial, or SEO-manipulated.

### Citation Failure

A generated claim may cite a real source that does not actually support that claim.

## Core Security Invariant

If an attacker completely succeeds in manipulating the research LLM, they may influence the quality or correctness of the research result, but they must not thereby gain access to secrets, internal systems, arbitrary network destinations, filesystem mutation, or consequential external actions.
